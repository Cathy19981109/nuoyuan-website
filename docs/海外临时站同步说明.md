# 海外临时站上线与数据同步说明

适用对象：需要把本机最新网站内容同步到海外临时展示站的操作人员。

---

## 一、临时站地址

| 用途 | 地址 |
|------|------|
| 官网前台 | https://nuoyuan-frontend.vercel.app |
| 后端 API | https://nuoyuan-website-production.up.railway.app |
| API 健康检查 | https://nuoyuan-website-production.up.railway.app/health |
| 代码仓库 | https://github.com/Cathy19981109/nuoyuan-website |

架构说明：

- 前台：Vercel（跟 GitHub `main` 自动部署）
- 后端：Railway（跟 GitHub `main` 自动部署）
- 数据库：Railway MySQL（与本机 MySQL 是两套库，需单独同步）

---

## 二、为什么本地改了线上不变？

1. **代码**：未推送到 GitHub `main`，Vercel / Railway 不会更新。
2. **内容**：产品、页面模块、配置在数据库里；只改本机后台，海外库不会自动变。
3. **图片**：上传文件在 `backend/uploads/`；需随代码推送或在海外后台重新上传。

因此每次完整更新需要：**推代码 → 等自动部署 → 同步数据库 → 保持海外站开放 → 验证**。

### 步骤 4：同步数据库（重点）

> **不要买 Navicat「数据传输」企业版。**  
> 使用免费方式：**运行 SQL 文件**。

#### 4.1 在 Navicat 连接 Railway MySQL

Navicat **没有**单独的「Railway」连接类型，请选普通 **MySQL**。

1. Navicat → 新建连接 → 选 **MySQL** → 下一步  
2. 打开 Railway → **MySQL** 服务 → **Variables**  
3. 查看 `MYSQL_PUBLIC_URL`（点眼睛），格式示例：

   `mysql://root:密码@主机.proxy.rlwy.net:端口/railway`

4. 拆开填入 Navicat：

| 字段 | 填什么 |
|------|--------|
| 连接名 | `railway`（若提示重名，改用 `railway-mysql`，或直接用已有连接） |
| 主机 | `@` 与最后一个 `:` 之间（如 `xxx.proxy.rlwy.net`） |
| 端口 | 最后一个 `:` 与 `/` 之间的数字（常不是 3306） |
| 用户名 | 一般为 `root` |
| 密码 | Variables 中的密码，或 URL 中 `:` 与 `@` 之间的部分 |
| 数据库 | `railway` |

5. **测试连接** → 成功 → 确定  

注意：

- **不要**用 `mysql.railway.internal`（仅 Railway 内网可用）  
- **不要**点「通过 URI 新建」粘贴整段 `mysql://...`（部分环境会报 `Scheme 'mysql' not supported`）  
- 若提示「Connection with same name already exists」：取消新建，改用左侧已有同名连接，或换一个连接名  

#### 4.2 准备 SQL 文件

本机路径：

`/Users/liuluyao/Desktop/Demo/docs/railway-sync-from-local.sql`

（由本机库导出；库名已改为 `railway`；末尾含海外站开放语句。此文件勿提交公开仓库。）

若文件过旧，可请开发人员重新导出后再同步。

#### 4.3 运行 SQL 文件（免费）

1. Navicat 双击连上 `railway`（或 `railway-mysql`）  
2. 左侧 **选中** 数据库 **`railway`**  
3. 右键该库 → **运行 SQL 文件…** / **执行 SQL 文件**  
4. 选择 `docs/railway-sync-from-local.sql`  
5. 点 **开始**  
6. 等待执行完成  

备选：选中 `railway` 库 → **查询 → 新建查询** → **文件 → 打开** 该 SQL → **运行**。

#### 4.4 确认海外站保持「开放」

本地库常把网站设为关闭。同步后务必确认海外为开放，否则前台会显示「即将上线」。

在 Railway 库新建查询并执行：

```sql
UPDATE nuoyuan_config SET config_value = '1' WHERE config_key = 'site_public_open';

INSERT INTO nuoyuan_config (config_key, config_value, name, description, sort)
SELECT 'site_public_open', '1', '网站对外开放', '海外临时站保持开放', 0
FROM DUAL
WHERE NOT EXISTS (
  SELECT 1 FROM nuoyuan_config WHERE config_key = 'site_public_open'
);

SELECT config_key, config_value FROM nuoyuan_config WHERE config_key = 'site_public_open';
```

结果应为 `config_value = 1`。

也可在海外管理后台 → 官网信息 / 网站中心 → **对外开放** 改为「开放」并保存。

## 五、常见问题

| 现象 | 处理 |
|------|------|
| 要花钱才能「数据传输」 | 改用「运行 SQL 文件」，不必购买企业版 |
| `Scheme 'mysql' not supported` | 不要用 URI 整段粘贴；选 MySQL 手动填主机端口 |
| 连接名已存在 | 使用已有连接，或改名新建 |
| 显示「即将上线」 | 执行步骤 4.4，把 `site_public_open` 设为 `1` |
| 官网还是旧版 | 等 Vercel Ready；强刷；确认域名正确 |
| 页面无数据 | 数据库未同步或 API 异常；查 health 并重做步骤 4 |
| Navicat 连不上 | 使用公网 Host/Port，不要用 `mysql.railway.internal` |
| 502 | Railway 后端未启动成功，查看 Deploy Logs |
| 国内有时打不开 | Vercel/Railway 在海外，临时演示可能不稳定；正式客户站用阿里云 |

## 六、与阿里云正式站的区别

| 项目 | 海外临时站 | 阿里云正式站 |
|------|------------|--------------|
| 用途 | 演示 / 内测 | 客户正式访问 |
| 前台 | Vercel | 阿里云服务器 / CDN |
| 后端与库 | Railway | 阿里云 ECS + RDS 等 |
| 网站开放开关 | 海外库保持 `1` | 可按客户上线节奏关闭/开放 |

客户正式上线请另见：`客户上线操作指引-阿里云.pdf`。
