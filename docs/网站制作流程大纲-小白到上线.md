> **文档用途：** 这是「一个月写完整套 SOP」的**总目录 / 骨架**，先定章节，再逐章填细节。  
> **适用对象：** 网站制作小白（以本机环境 + Cursor / VS Code + GitHub + 数据库 + 上线为主线）。  
> **对应项目：** `nuoyuan-website`（前台 `frontend` + 后台 `Auth` + 接口 `backend` + MySQL）。  
> **写作用法：** 每章下的「待写 SOP」打钩后再扩写成独立操作手册；「网课链接」由你自行粘贴 B 站等地址。

| 周次 | 建议写完的大章 | 目标 |

写作原则：

1. **先写「你做过什么」**，再补「为什么这样做」。  
2. **每一步都要有截图位**（用 `【截图：……】` 占位，之后补图）。  
3. **命令、路径、账号名写死成可复制**；密码只写「存在哪里」，不要写进公开仓库。  
4. 已有手册可交叉引用，不必重复抄：  
   - 《海外临时站同步说明》  
   - 《服务商上线操作手册-阿里云》  
   - 《客户上线操作指引-阿里云》

```text
        ↓

   电脑装软件 → Cursor/VS Code → 终端 → Node/npm → Git
        ↓

        ↓

        ↓

        ↓
【运维与复盘】
   改内容怎么发版、图片怎么传、出问题怎么查、账号怎么交
```

## 第 0 章 · 先搞懂：这个网站到底由几块组成？

**学习目标：** 能用自己的话画出「访客 / 管理员 / 数据库」三条线。

### 0.1 诺元官网的三端一库

| 名称 | 仓库目录 | 本机常见地址 | 干什么 |
|------|----------|--------------|--------|
| 官网前台 | `frontend/` | `http://localhost:5173` | 访客看到的页面 |
| 管理后台 | `Auth/` | `http://localhost:5174` | 改导航、产品、新闻、配置 |
| 后端 API | `backend/` | `http://localhost:3000` | 提供接口、登录鉴权、上传文件 |
| 数据库 | MySQL（库名如 `nuoyuan_website`） | `127.0.0.1:3306` | 存真正内容 |

### 0.2 必须分清的三个「环境」

| 环境 | 典型地址 | 数据库 | 用途 |
|------|----------|--------|------|
| 本机开发 | localhost | 本机 MySQL | 自己改、自己看 |
| 海外临时站 | Vercel 前台 + Railway API | Railway MySQL（另一套库） | 给别人预览，未备案也能看 |
| 国内正式站 | 客户域名 + 阿里云等 | 服务器上的 MySQL | 备案后对公众开放 |

> 核心坑：**本机改了后台 ≠ 线上自动变**。代码要推 GitHub；库内容要单独同步。

## 第 3 章 · Git 与 GitHub（代码怎么存、怎么协作）

**学习目标：** 理解「本机文件夹」和「GitHub 仓库」的关系；会 push；知道 main 是什么。

### 3.1 概念对照

| 说法 | 含义 |
|------|------|
| 仓库（repository） | 一整份项目代码（如 `Cathy19981109/nuoyuan-website`） |
| 克隆（clone） | 从 GitHub 拉到本机 |
| 提交（commit） | 给改动拍一张「快照」并写说明 |
| 推送（push） | 把本地提交传到 GitHub |
| 分支（branch） | 平行试验线；正式常用 `main` |
| PR（Pull Request） | 请求把某分支合并进另一分支（可与 Cursor / 协作者配合） |

### 3.2 和本项目相关的真实链路

1. 本机改代码  
2. `git add` → `git commit` → `git push origin <分支>`  
3. 合并进 `main` 后：  
   - Vercel / Railway 常会跟 `main` **自动部署**  
   - 国内服务器则常需 **手动拉代码 / 重新构建**（见第 9 章）

### 3.3 本章待写 SOP

- [ ] SOP-3A：注册 / 登录 GitHub；SSH Key 或 HTTPS 登录怎么配  
- [ ] SOP-3B：第一次 clone 本仓库到本机指定目录  
- [ ] SOP-3C：日常改完代码的标准五步（status → add → commit → push → 网页确认 Commit）  
- [ ] SOP-3D：分支怎么开、怎么合并回 `main`（含你真实用过的分支名示例）  
- [ ] SOP-3E：什么文件绝不能提交（`.env`、密码、大体积隐私 SQL）——对照 `.gitignore`
