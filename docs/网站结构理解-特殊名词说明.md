## A. 关系概览（整张流程图会碰到的词）

| 名词 | 是什么 | 形象理解 | 在流程图里的位置 |
|------|--------|----------|------------------|
| **网站结构** | 网站由哪几部分组成、彼此怎么配合 | 餐厅：厅堂、后厨窗口、仓库怎么分工 | 整张图 |
| **用户 / 网站访客** | 打开官网来看内容的人 | 进店吃饭的客人 | 图的最左侧 |
| **网站管理员** | 登录管理页、负责改内容的人 | 店员在内部系统里改菜单 | 也在最左侧（入口不同） |
| **前端** | 眼睛能看到、鼠标能点到的网页 | 餐厅的堂食区域 / 点餐屏 | 人右边第一块 |
| **后端 / 后端程序** | 在电脑或服务器上跑的中介程序 | 后厨里接单、取货、回传的人 | 中间那块 |
| **数据库** | 专门存放网站真正内容的仓库软件 | 食材与菜单资料仓库 | 最右侧 |
| **请求** | 一方向另一方发出的“请帮我做某事” | 你喊：“请给我产品列表” | 从前到后的箭头 |
| **返回 / 响应** | 对方把结果送回来 | 窗口把餐递回来 | 从后到前的箭头 |
| **增 / 删 / 改 / 查** | 对数据的四种基本操作：增加、删除、修改、查询 | 往仓库放货、扔掉、改标签、查找 | 后端 ↔ 数据库 |

一句话总览：

**人 → 前端 → 后端 → 数据库 → 再原路返回。**

---

## B. 前端板块

| 名词 | 是什么 | 形象理解 |
|------|--------|----------|
| **前端** | 网页这一层（展示 + 点击操作） | 你看得见的店面 |
| **前台** | 给访客看的官网页面 | 临街橱窗与菜单展示 |
| **后台 / 管理后台** | 给管理员改网站内容的管理页 | 员工内部操作台 |
| **页面** | 浏览器里打开的一屏内容 | 一张张可翻的店内说明牌 |
| **浏览器** | 用来打开网页的软件（如 Chrome） | 你走进网站世界的大门 |

补充：前台和后台都算前端，因为都是页面；只是给不同人用，入口不同。

---

## C. 接口板块

| 名词 | 是什么 | 形象理解 | 在流程图里的位置 |
|------|--------|----------|------------------|
| **接口** | 前端向后端要数据、交任务时的约定窗口 | 餐厅出餐/点餐窗口 | **前端 ↔ 后端** 之间 |
| **API** | 接口的英文说法，意思相同 | 同上，只是英文名 | 同上 |

**不算接口的地方：**

- 人点击页面：那是人与前端的互动  
- 后端进出数据库：那是后端在仓库作业（常用下面的 SQL）

---

## D. 后端板块

| 名词 | 是什么 | 形象理解 |
|------|--------|----------|
| **后端** | 接收请求、处理规则、读写数据库、再把结果送回前端的程序 | 中介 / 后厨接单员 |
| **服务器** | 能 24 小时（或长时间）在网上提供服务的电脑 | 放在机房里、一直上班的电脑 |
| **编程语言** | 写程序用的“说明书语言” | 给电脑下命令时用的一种文字规则 |
| **JavaScript** | 一种编程语言；你这个网站的主要说明书语言 | 本店厨房通用语 |
| **Node** / **Node.js** | 让电脑（不只是浏览器）也能运行 JavaScript 的发动机 | 让同一种燃料也能开“后端货车”的发动机 |
| **依赖** | 项目要正常运行，需要事先装好的现成零件 | 开店必备的酱油、锅具（不必自己从零造） |
| **npm** | 跟 Node 常一起出现的零件安装小助手 | 按清单把乐高零件自动买齐装好的助手 |

说明：

- 你的后端主要用 **JavaScript** 写  
- 因为有了 **Node**，这些 JavaScript 才能在浏览器外面跑  
- 安装现成零件时，会用到 **npm**

---

## E. 数据库板块

| 名词 | 是什么 | 形象理解 |
|------|--------|----------|
| **数据库** | 专门存、管数据的仓库软件（大类名称） | “仓库软件”这一品类 |
| **MySQL** | 数据库的一种；你这个网站正在用的仓库 | 你租用的那一家具体仓库品牌 |
| **表** | 数据库里一张张整齐的格子清单 | 仓库货架上的分类表格 |
| **数据** | 存进去的具体内容（产品名、新闻、配置等） | 货架上的货物与标签信息 |
| **SQL** | 跟数据库说话的专用句子 | 对仓库管理员说的规范用语 |
| **Navicat** | 用鼠标管理数据库的软件 | 仓库的图形化遥控器（少手写 SQL） |

补充：数据库不止 MySQL 一种。其他常见名字还有 PostgreSQL、SQL Server、SQLite、MongoDB 等。现在只需记住：**你的站用 MySQL。**

## F. 本阶段常提到的工具（先认门牌）

这些词更多属于“工具箱”，本阶段能认出即可：

| 名词 | 是什么 | 形象理解 |
|------|--------|----------|
| **Cursor** | 写代码、看项目文件的编辑器 | 你的工作台 |
| **GitHub** | 在网上存放代码的仓库 | 代码的云端保险箱 |
| **Vercel** | 常用来把前台等网页放到网上的托管平台 | 帮你把橱窗搬到街上的服务商 |
| **Railway** | 常用来把后端和云端数据库跑在网上的托管平台 | 帮你把后厨和仓库搬到云端的服务商 |

## G. 易混词对照（务必看）

| 你可能听到的 | 正确理解 | 别和它搞混 |
|--------------|----------|------------|
| **JSON**（有人会误写成 Jason） | 双方都看得懂的**数据快递单格式**；不是编程语言 | 不是 JavaScript，也不是人名 Jason |
| **JavaScript** | 编程语言（说明书） | 不是 Java |
| **Java** | 另一种编程语言 | 不是 JavaScript |
| **Python** | 另一种编程语言，常用于脚本、学习、别的项目 | 不是你这个官网的主语言 |
| **接口 / API** | 前端 ↔ 后端 的服务窗口 | 不是电脑机箱后面的网线插口 |
| **Node** | 运行 JavaScript 的发动机（运行环境的一种） | 不是“你电脑里全部开发环境”的总和 |
| **环境**（一词多义） | ① Node 这种运行环境；② 电脑上装的一整套工具；③ 本机/临时站/正式站这些场地 | 同一个中文词，场景不同意思不同 |
| **MySQL** | 一种数据库 | 不是“数据库”这个大类的唯一答案 |
| **SQL** | 跟数据库说话的句子 | 不是数据库软件本身 |
| **依赖** | 项目需要的现成零件 | 不是“依赖某人”的日常口语意思 |

## H. 一张纸版速记（可单独贴在笔记最上）

1. **前端**：看得见的页面（前台给访客，后台给管理员）  
2. **接口（API）**：前端和后端之间的服务窗口  
3. **后端**：中介程序；你的站主要用 JavaScript，并靠 Node 跑起来  
4. **数据库**：内容仓库；你的站用 MySQL；说话用 SQL；可用 Navicat 点着管  
5. **JSON**：接口传数据时常用的快递单格式  
6. **npm**：安装依赖（现成零件）的小助手  
7. **Java ≠ JavaScript**；**JSON ≠ 编程语言**
