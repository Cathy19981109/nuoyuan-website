# 诺元智合官网上线 — 客户操作指引（阿里云）

> **适用对象：** 网站归属公司（客户）与服务方对接人员  
> **原则：** 云账号、域名、备案、服务器与费用须落在**客户公司主体**名下；服务方负责技术部署与协助，不长期用个人/服务方账号托管客户官网。

---

## 〇、一页看懂：谁做什么

### 客户必须亲自完成（无法代办）

| 事项 | 说明 |
|------|------|
| 阿里云**企业实名** | 营业执照、法人核验、短信/人脸 |
| **域名**注册与实名 | 与企业主体一致 |
| 购买**国内**云服务器 | 费用由客户账户支付，便于发票与资产归属 |
| **ICP 备案**提交与核验 | 负责人证件、人脸/短信；材料真实性由客户负责 |
| 开通服务方**协作权限**（推荐） | 子账号/协作者，勿直接给主账号密码 |
| 提供官网展示信息 | 电话、地址、邮箱、版权、询价接收邮箱等 |
| **内容验收**与正式「对外开放」 | 确认无误后，在后台将开关改为开放并保存 |
| 账号与费用持续保管 | 续费、备案年审、密码保管责任在客户 |

### 服务方负责完成（技术交付）

| 事项 | 说明 |
|------|------|
| 指导客户完成采购与备案选项 | 远程看截图指导；核验码仍由客户点 |
| 服务器环境安装与加固协助 | 系统、Nginx、Node、MySQL、防火墙等 |
| 部署前台、管理后台、后端 API | 绑定域名、配置 HTTPS 证书 |
| 导入/迁移网站数据与上传资源 | 产品、页面模块、图片等（按合同范围） |
| 配置「对外开放」默认关闭 | 验收前访客只看到「即将上线」 |
| 提供后台账号与预览方式 | 并协助客户完成上线前验收 |
| 上线当天协助正式开放与复查 | DNS、HTTPS、前台/后台、询价等抽检 |
| 约定范围内的售后与培训 | 按合同：改内容指导、故障协助等 |

### 双方配合节点（时间线）

```text
客户：企业实名 → 域名 → 买服务器 → 交备案
                ↓（随时把 IP / 协作权限发给服务方）
服务方：可同步装环境、部署代码（用 IP 或临时域名验收）
                ↓
客户：备案通过 → 通知服务方
服务方：解析域名 + HTTPS → 交付验收
客户：预览验收 → 后台「对外开放」= 开放 → 正式上线
```

预计：采购当天可完成；备案审核常见为**数个工作日至数周**（以管局为准）。**未备案通过前，不建议用正式域名对公众开放。**

## 一、为什么必须用客户公司主体？

域名实名、云服务器、ICP 备案均须绑定**公司营业执照主体**。账号与资产在客户名下，便于：

- 合规备案与后续年审  
- 费用、发票归属清晰  
- 日后更换服务方时，网站仍归属客户  

服务方可协助填写资料、部署网站；**法人核验、短信验证、人脸识别等环节必须客户配合完成**，服务方无法合法代做。

## 六、客户操作步骤（分步）

### 步骤 1：注册阿里云（企业账号）

1. 打开 [https://www.aliyun.com](https://www.aliyun.com)  
2. 注册账号，选择**企业实名认证**  
3. 按提示上传营业执照、法人信息并完成核验  
4. （推荐）在控制台为服务方开通**子账号/协作者**，仅授予运维所需权限，勿交出主账号密码  

完成后请告知服务方：**阿里云登录账号（主账号可打码）、是否已开通协作权限**。

---

### 步骤 2：注册域名

1. 进入阿里云「域名」产品页  
2. 查询并注册官网域名（如 `yourbrand.com`）  
3. 完成**域名实名认证**（与企业主体一致）  
4. 记录已注册的完整域名，发给服务方  

说明：未备案前，域名可能暂时无法在中国大陆稳定访问，属正常现象。

建议同时规划两个主机名（可由服务方协助配置解析）：

- `www.您的域名.com` → 官网前台  
- `admin.您的域名.com` → 管理后台  

---

### 步骤 3：购买云服务器

1. 推荐优先看「**轻量应用服务器**」或「云服务器 ECS」新人套餐  
2. 关键注意：  
   - **地域**：选择中国内地（如公司所在省份或就近地域），便于备案  
   - **系统镜像**：Ubuntu 22.04（或服务方指定版本）  
   - **带宽**：官网起步常见 3Mbps～5Mbps，可按访问量再升配  
3. 购买完成后，在控制台放行安全组/防火墙：**80、443**（以及 SSH 22，仅限运维需要）  
4. 将以下信息发给服务方（可通过安全渠道）：  
   - 服务器公网 IP  
   - 登录方式（密钥或临时密码，首次登录后请修改）  
   - 地域与配置截图  

费用建议由客户账户支付，便于开具发票、资产归属清晰。

> 可选（按合同）：若访问量较大或需更高可用，服务方可能建议另购云数据库 RDS、对象存储 OSS 等，仍建议挂在客户账号下。

---

### 步骤 4：提交 ICP 备案

1. 登录阿里云控制台 → 搜索「**ICP 备案**」  
2. 按向导填写：  
   - 主体：公司营业执照信息  
   - 网站：网站名称、域名、服务内容（企业官网）  
   - 负责人：按要求上传证件并完成核验（人脸/短信）  
3. 网站服务内容如实填写「企事业单位网站」等（以页面选项为准）  
4. 提交后等待初审、管局审核；留意短信/邮件，及时补正材料  

备案期间服务方可同步准备部署；**正式用域名对公众开放，须等备案通过**。

---

### 步骤 5：备案通过后（客户通知服务方）

请通知服务方并共同确认：

1. 域名已解析到服务器  
2. 已配置 HTTPS 证书  
3. 管理后台、前台均可正常打开  
4. 客户完成内容验收后，在管理后台将「**对外开放**」设为开放并保存（见第四节）  

客户可用无痕浏览器访问正式域名做最终验收。

## 七、服务方交付清单（客户可据此催办/验收）

服务方在拿到服务器协作权限（或 SSH）后，通常按下列顺序交付。客户可用本表勾选进度：

### 7.1 部署前准备

- [ ] 确认服务器地域、系统、安全组（80/443/22）  
- [ ] 确认客户已开通协作权限或提供安全的登录方式  
- [ ] 确认目标域名：`www` / `admin`（及是否需要根域名跳转）  

### 7.2 环境与部署

- [ ] 安装运行环境（如 Node.js、MySQL、Nginx、进程守护等）  
- [ ] 部署后端 API，配置生产环境变量（数据库、上传目录等）  
- [ ] 构建并部署官网前台、管理后台静态资源  
- [ ] 配置反向代理：前台 / 后台 / API 路由正确  
- [ ] 申请并自动续期 HTTPS 证书（Let's Encrypt 或阿里云证书）  

### 7.3 数据与内容

- [ ] 导入约定范围内的网站数据（导航、产品、服务、新闻、页面模块等）  
- [ ] 迁移或上传图片、视频等媒体文件，确认前台可显示  
- [ ] 配置官网信息（品牌 Logo、联系方式等，以客户提供文案为准）  
- [ ] 「对外开放」保持**关闭**，直至客户书面/口头确认可开放  

### 7.4 账号与培训

- [ ] 交付管理后台登录地址与初始账号（督促客户**立即修改密码**）  
- [ ] 说明内容维护路径：产品/服务/新闻/页面编辑/询价等（按合同范围培训）  
- [ ] 说明预览方式：`/?preview=1` 或后台「前台预览」  

### 7.5 正式上线日

- [ ] 备案号已取得，DNS 已生效  
- [ ] HTTPS 无浏览器报警  
- [ ] 前台、后台、询价提交抽检通过  
- [ ] 客户确认后打开「对外开放」并保存  
- [ ] 双方各留一份：域名、后台地址、负责人联系方式

完成采购与备案进度后，请汇总发送下面清单。  
**每一项是什么、为什么要、怎么填**见下表；发给服务方后，服务方会按「第十节」继续操作。

### 9.1 勾选清单（汇总用）

- [ ] 企业全称、统一社会信用代码  
- [ ] 阿里云企业账号（主账号可部分打码）及协作权限说明  
- [ ] 已注册域名列表（含是否已实名）  
- [ ] 服务器公网 IP、地域、登录方式  
- [ ] ICP 备案号（备案通过后）  
- [ ] 官网对外展示的联系电话、地址、邮箱、版权文案  
- [ ] 询价接收邮箱（及是否已准备企业邮箱 SMTP，如需）  
- [ ] 希望对外正式开放的目标日期（便于服务方排期）  

### 9.2 每一项详细说明（给客户看）

#### 1）企业全称、统一社会信用代码

| | |
|------|------|
| **是什么** | 营业执照上的公司正式名称，以及 18 位统一社会信用代码。 |
| **为什么要** | 备案主体、网站页脚/关于我们、合同与发票主体必须一致；服务方录入官网信息时也要对齐全称。 |
| **怎么发** | 可发营业执照清晰照片，或打字：`XX有限公司` + `91XXXXXXXXXXXXXX`。 |
| **注意** | 全称不要用简称、品牌名代替（如执照是「某某生物科技有限公司」，不要只写「某某生物」）。 |

#### 2）阿里云企业账号及协作权限说明

| | |
|------|------|
| **是什么** | 客户用来登录阿里云控制台的企业主账号标识（手机号/邮箱可部分打码），以及是否已给服务方开通子账号/协作者。 |
| **为什么要** | 服务方需在控制台协助看服务器、安全组、域名解析、备案进度；**不要**把主账号密码发给服务方。 |
| **怎么发** | 示例：`主账号手机尾号 ****1234；已开通 RAM 子账号 ops@xxx.onaliyun.com，权限：ECS/轻量 + 域名解析 + 备案只读`。 |
| **注意** | 只开最小权限；项目结束后客户可关闭协作。验证码/人脸仍由客户完成。 |

#### 3）已注册域名列表（含是否已实名）

| | |
|------|------|
| **是什么** | 已购买并打算用于官网的域名，例如 `example.com`，并说明是否已完成域名实名。 |
| **为什么要** | 服务方要配置 `www`（前台）、`admin`（后台）解析与 HTTPS 证书；未实名往往无法顺利备案和解析生效。 |
| **怎么发** | 示例：`example.com（已实名）；计划 www.example.com 做官网，admin.example.com 做后台`。 |
| **注意** | 若还有旧域名、跳转域名，一并写出，避免漏配。 |

#### 4）服务器公网 IP、地域、登录方式

| | |
|------|------|
| **是什么** | 云服务器的公网 IP；购买时选择的地域（如华东2-上海）；SSH 登录方式（密钥文件或首次密码）。 |
| **为什么要** | 没有 IP 与登录方式，服务方无法安装环境、部署网站；地域需与备案一致。 |
| **怎么发** | 示例：`IP 47.xx.xx.xx；地域 华东2（上海）；Ubuntu 22.04；SSH 用户 root；密钥已通过加密渠道发送`。 |
| **注意** | 密码/密钥请用微信文件传输助手加密压缩或当面交付，**不要**发在公开群；首次登录后请客户或服务方协助立即改密。安全组需已放行 **22、80、443**。 |

#### 5）ICP 备案号（备案通过后）

| | |
|------|------|
| **是什么** | 管局审核通过后的备案号，常见格式类似 `沪ICP备XXXXXXXX号` / `粤ICP备XXXXXXXX号`。 |
| **为什么要** | 国内网站页脚依法需展示备案号并链到工信部查询页；也是「可以用正式域名对外开放」的标志之一。 |
| **怎么发** | 备案通过短信/控制台截图，或直接复制完整备案号文字。 |
| **注意** | **未通过前可以先部署、先内测**；但不要把「对外开放」打开给公众。通过后马上发给服务方挂页脚。 |

#### 6）官网对外展示的联系电话、地址、邮箱、版权文案

| | |
|------|------|
| **是什么** | 会出现在官网页脚、「联系我们」等位置的对外信息。 |
| **为什么要** | 服务方按客户提供的文案写入「官网信息」/页面模块，避免写错电话或旧地址。 |
| **怎么发** | 建议按模板：联系电话 / 地址 / 对外邮箱 / 版权行（如 `© 2026 某某有限公司 版权所有`）。 |
| **注意** | 对外电话建议是能接听的商务号；与备案填报信息不冲突即可。 |

#### 7）询价接收邮箱（及是否已准备企业邮箱 SMTP）

| | |
|------|------|
| **是什么** | 访客在官网点「立即询价」后，通知要发到哪个邮箱；若需系统自动发信，是否已有企业邮箱的 SMTP 账号。 |
| **为什么要** | 配好后，客户才能在邮箱里收到询价线索；仅填接收邮箱、不配 SMTP 时，可能只能在后台「询价管理」里查看（以实际部署为准）。 |
| **怎么发** | 示例：`接收：sales@example.com；SMTP：已开通企业邮箱，主机 smtp.exmail.qq.com，端口 465，账号同左（密码另发）`。若暂无 SMTP，写「暂无，先只看后台询价列表」。 |
| **注意** | SMTP 密码属敏感信息，单独安全渠道发送；不要写进公开文档。 |

#### 8）希望对外正式开放的目标日期

| | |
|------|------|
| **是什么** | 客户希望公众能打开完整官网（「对外开放 = 开放」）的大致日期。 |
| **为什么要** | 服务方据此排期：解析、证书、数据导入、联调、培训、上线日值班。 |
| **怎么发** | 示例：`目标 2026-09-15 对外开放；此前 9/10–9/14 内部验收`。 |
| **注意** | 须晚于或等于 **ICP 备案通过日**；若备案延误，开放日顺延。 |

## 十、服务方收到上述信息后怎么操作

> 本节给**服务方（你）**使用：客户把第九节清单发来后，按收到的进度分阶段执行。可与第七节交付清单对照勾选。

### 10.1 刚收到「企业信息 + 域名 + 服务器」时（备案可能尚未通过）

1. **核对主体**  
   - 企业全称、信用代码与合同、阿里云实名、域名实名是否一致。  
   - 不一致先让客户改，再部署，避免备案和页脚返工。

2. **确认协作登录**  
   - 用客户开通的子账号登录阿里云，检查：服务器状态、安全组（22/80/443）、域名是否在该账号下。  
   - 用客户提供的 SSH 密钥/密码登录服务器，**立刻建议改密或换成服务方运维密钥（仍归客户资产）**。

3. **在服务器上部署**（可与备案并行）  
   - 安装运行环境（Node、MySQL、Nginx、进程守护等）。  
   - 部署后端、前台、管理后台。  
   - 先用 **公网 IP** 或临时主机名做内部访问（按你的习惯配置），**「对外开放」保持关闭**。  
   - 导入约定数据与图片；把客户给的电话/地址/邮箱/版权写入官网信息（可先不填备案号）。

4. **配置询价**  
   - 后台填入询价接收邮箱。  
   - 若客户提供了 SMTP：写入环境变量/站点配置并发一封测试询价。  
   - 若无 SMTP：确认后台「询价管理」能看到提交记录，并告知客户暂时在后台查线索。

5. **回传给客户**  
   - 后台地址（此时可能是 IP 或临时域名）、初始账号密码（要求客户登录后改密）。  
   - 预览方式：`/?preview=1` 或后台「前台预览」。  
   - 说明：备案通过前不要对公众宣传正式域名。

### 10.2 客户发来「域名已实名」且可解析时

1. 在阿里云 **域名解析** 增加（或请客户授权你操作）：  
   - `www` → 服务器公网 IP（A 记录）  
   - `admin` → 同一 IP（A 记录）  
   - 按需配置根域名 `@` 跳转到 `www`  
2. 等解析生效后，为 `www`、`admin` 申请 **HTTPS 证书**并配置到 Nginx。  
3. 用 `https://www.…`、`https://admin.…` 自测打开；证书报警则排查解析/证书域名是否匹配。

### 10.3 客户发来「ICP 备案号」后

1. 将备案号写入官网页脚/官网信息（按现有后台字段或页脚配置）。  
2. 确认备案号可点击跳转工信部查询（若站点已支持链接）。  
3. **仍保持「对外开放 = 关闭」**，直到客户完成验收并确认开放日。

### 10.4 接近客户给出的「正式开放日」

1. 与客户过一遍**第八节验收清单**。  
2. 抽检：手机端、询价、主要栏目、图片。  
3. 客户确认后：指导客户（或在授权下代为）在  
   `管理后台 → 官网信息 → 对外开放 → 开放 → 保存`。  
4. 用无痕窗口打开正式域名，确认不再是「即将上线」。  
5. 交付收尾：改密确认、对接人联系方式、简单操作培训、质保说明。

### 10.5 信息缺失时怎么催

| 缺什么 | 影响 | 服务方可先做什么 |
|--------|------|------------------|
| 无服务器 IP/登录 | 无法部署 | 只能远程指导客户买机、开安全组 |
| 无域名 | 无法配正式 HTTPS 主机名 | 可用 IP 内测 |
| 无备案号 | 不能合规对公众开放 | 可部署+预览，不打开「对外开放」 |
| 无联系方式文案 | 页脚/联系页空白或占位 | 用「待客户提供」占位，上线前必须换成正式文案 |
| 无询价邮箱 | 线索可能漏接 | 先开后台询价列表，并书面提醒客户每天登录查看 |
| 无开放日 | 排期不清 | 默认「备案通过后 +3～5 个工作日验收再开」 |

### 10.6 建议你本地留存的交付记录（勿发给无关人员）

- 客户全称、域名、`www`/`admin` 最终地址  
- 服务器 IP、地域、SSH 方式（密码勿明文长期存放）  
- 备案号、开放日期、后台管理员是否已改密  
- SMTP 是否已通、测试询价时间  
- 协作子账号名称（方便日后回收权限提醒客户）

## 十二、常见问题

**Q：可以让服务方用他们的账号先上线吗？**  
不建议。主体不一致会导致备案、过户、发票和后续维护风险。临时演示可用服务方提供的**海外临时站**，与阿里云正式站分开。

**Q：备案要多久？**  
各地管局不同，常见为数个工作日至数周，以阿里云备案进度与短信通知为准。

**Q：备案没过之前，外面能打开网站吗？**  
国内用域名正式访问通常受限。关闭状态下访客看到「即将上线」；内部可用预览链接或服务器 IP（由服务方配置）验收。

**Q：个人认证能不能备案企业官网？**  
企业官网应使用**企业主体**账号与材料备案。

**Q：服务方要主账号密码怎么办？**  
不要给。请开通**子账号/RAM 协作者**，按最小权限授权；SSH 可用独立密钥，并可随时回收。

**Q：上线后谁改产品文案、发新闻？**  
一般由客户在管理后台自行维护；服务方按合同提供操作培训或代运营。

**Q：海外临时演示站和阿里云正式站是一回事吗？**  
不是。海外站（如 Vercel + Railway）仅用于演示/内测；客户国内正式访问应使用本指引的阿里云方案。

**Q：客户只发了清单里的一部分，服务方能开工吗？**  
可以部分开工：有服务器即可部署内测；有域名可配解析与证书；有备案号才能合规对公众开放。缺哪项按第十节「信息缺失时怎么催」处理。
