# 诺元智合官网上线 — 服务商操作手册（阿里云）

> **适用对象：** 服务方（内部使用，一般不发给客户）  
> **客户阅读版：** 同目录《客户上线操作指引-阿里云》（发 PDF 给客户）  
> **原则：** 账号、域名、备案、服务器、费用落在**客户主体**；你负责技术部署与协助，不长期用个人/我方账号托管客户官网。

---

## 一、职责与时间线（你要盯的）

### 1.1 客户必须亲自做（你只能指导，不能代核验）

- 阿里云企业实名、域名实名  
- 国内买服务器并付费  
- ICP 备案人脸/短信核验  
- 开通你的协作权限（推荐 RAM 子账号）  
- 提供对外文案、询价邮箱、目标开放日  
- 验收后确认「对外开放」  

### 1.2 你负责交付

- 远程指导采购/备案选项（截图指导）  
- 环境安装与加固协助（Nginx / Node / MySQL 等）  
- 部署前台、后台、API；域名解析 + HTTPS  
- 按合同导入数据与媒体  
- 「对外开放」默认**关闭**直至客户确认  
- 交付账号、培训、上线日复查、约定售后  

### 1.3 时间线

```text
客户：实名 → 域名 → 买机 → 交备案
           ↓（IP / 协作权限到手即可开工）
你：装环境、部署、IP/临时方式内测（开关关闭）
           ↓
客户：备案通过 → 发备案号
你：解析 + HTTPS + 页脚备案号 → 约验收
客户：验收通过 → 开「对外开放」→ 正式上线
```

未备案通过：**可部署、可预览，不对公众开放。**

## 1.4 怎么确认「这个网站要按 Linux 部署」？（给你自查）

客户电脑是 Mac 还是 Windows **不算数**。要看的是：**生产服务器准备怎么装这套代码**。

### 对本仓库（诺元智合官网）——已经确定用 Linux / Ubuntu

依据（任一条都能说明问题）：

| 看哪里 | 你看到什么 | 说明什么 |
|--------|------------|----------|
| 本手册 §1.2 / §3.2 | 写的是 Nginx、Node、MySQL、进程守护、HTTPS | 这是国内 **Linux 云主机**常见装法，不是 Windows IIS |
| 《客户上线操作指引》步骤 3 | 明确要求客户买 **Ubuntu 22.04** | 交付标准已写死 Linux |
| 项目结构 | `frontend` + `Auth`（Vue）+ `backend`（Node/Express）+ MySQL | 国内正式站通常：Linux 上跑 Node + Nginx 反代 |
| 海外临时站 | Railway / Vercel 容器环境 | 底层也是 Linux，不是 Windows Server |
| 仓库里 | 没有 Windows 专用部署说明（无 IIS / `.bat` 生产流程） | 未按 Windows 服务器交付设计 |

> 补充：Node 理论上也能装在 Windows Server 上，但**本项目的交付文档、端口、证书、运维习惯都按 Ubuntu 写死了**。给客户买机时不要选 Windows。

### 以后给其他客户做网站——下单前在这些地方检查

按顺序查，查到一条能定案即可：

1. **交付/部署文档**  
   搜：`Ubuntu`、`CentOS`、`Linux`、`Nginx`、`IIS`、`Windows Server`。  
   - 写 Nginx / apt / systemd / Ubuntu → **买 Linux**  
   - 写 IIS / `.aspx` / Windows Server → **才考虑 Windows**

2. **Dockerfile / docker-compose**（若有）  
   - `FROM node:…`、`FROM ubuntu`、`FROM nginx` → **Linux**  
   - `FROM mcr.microsoft.com/windows…` → Windows 容器（少见）

3. **部署脚本**  
   - 只有 `.sh`、命令是 `apt install`、`systemctl`、`nginx -t` → **Linux**  
   - 主要是 `.ps1` / `.bat`、`iisreset` → Windows

4. **CI 配置**（GitHub Actions 等）  
   - `runs-on: ubuntu-latest` → 按 Linux 构建/测试  
   - `windows-latest` 且用于部署 → 再核实是否真要 Windows 主机

5. **技术栈常识（没有文档时）**  

| 常见栈 | 国内云主机通常选 |
|--------|------------------|
| Vue/React + Node + MySQL/Postgres | **Linux（推荐 Ubuntu LTS）** |
| PHP + Nginx/Apache + MySQL | **Linux** |
| Java Spring + Nginx | **Linux** |
| 纯 .NET Framework + IIS | Windows Server |
| 静态站 + Nginx | **Linux** |

6. **仍不确定**  
   问开发/查合同技术附件，**确认后再让客户付款买机**。不要默认 Windows。

### 自检口诀

> **文档写 Ubuntu/Nginx → Linux；只有 IIS/.NET Framework 老栈 → 才看 Windows。**  
> **诺元这套官网：固定 Ubuntu 22.04。**

## 二、向客户催要的信息（对照客户版第八节）

客户应汇总发给你：

| # | 信息 | 你拿来做什么 |
|---|------|----------------|
| 1 | 企业全称、统一社会信用代码 | 核对合同/备案/页脚主体一致 |
| 2 | 阿里云账号标识 + 协作权限说明 | 登控制台看机器、安全组、解析、备案进度（不要主账号密码） |
| 3 | 域名列表及是否实名 | 配 `www` / `admin`、申请证书 |
| 4 | 公网 IP、地域、SSH 登录方式 | 登录部署；核对地域与备案一致 |
| 5 | ICP 备案号（通过后） | 页脚展示；具备合规开放条件 |
| 6 | 电话、地址、邮箱、版权文案 | 写入官网信息/页脚/联系我们 |
| 7 | 询价接收邮箱 + 是否有 SMTP | 配通知；测询价 |
| 8 | 目标正式开放日 | 排期验收与上线值班 |

敏感信息（SSH 密码、SMTP 密码）要求客户走加密渠道，勿留在公开群。

## 三、交付清单（内部勾选）

### 3.1 部署前

- [ ] 服务器地域、系统、安全组 22/80/443  
- [ ] 协作账号或 SSH 可用  
- [ ] 确认目标主机名：`www` / `admin`（及根域跳转）  

### 3.2 环境与部署

- [ ] Node / MySQL / Nginx / 进程守护  
- [ ] 后端 API + 生产环境变量（库、上传目录等）  
- [ ] 前台、管理后台构建与部署  
- [ ] 反向代理：前台 / 后台 / API 路由正确  
- [ ] HTTPS 证书申请与自动续期  

### 3.3 数据与内容

- [ ] 按合同导入导航、产品、服务、新闻、页面模块等  
- [ ] 媒体文件可访问  
- [ ] 写入客户提供的联系与版权文案  
- [ ] 「对外开放」= **关闭**  

### 3.4 账号与培训

- [ ] 交付后台地址与初始账号，督促**立即改密**  
- [ ] 培训：产品/服务/新闻/页面/询价（按合同）  
- [ ] 说明预览：`/?preview=1` 或后台「前台预览」  

### 3.5 正式上线日

- [ ] 备案号已挂页脚，DNS 生效，HTTPS 正常  
- [ ] 前台/后台/询价抽检通过（含手机端）  
- [ ] 客户确认后打开「对外开放」并保存  
- [ ] 双方留存：域名、后台地址、对接人

## 四、收到客户信息后怎么操作（分阶段）

### 4.1 刚有「企业信息 + 域名 + 服务器」（备案可能未过）

1. **核对主体**  
   全称、信用代码与合同、阿里云实名、域名实名一致；不一致先让客户改。

2. **确认协作登录**  
   - 子账号登阿里云：机器状态、安全组、域名是否在该账号下  
   - SSH 登录后建议改密或换运维密钥（资产仍归客户）

3. **部署（与备案并行）**  
   - 装环境 → 部署后端/前台/后台  
   - 先用公网 IP 或临时方式内测  
   - **保持「对外开放」关闭**  
   - 导入数据；写入联系文案（备案号可后补）

4. **询价**  
   - 填接收邮箱  
   - 有 SMTP：写入配置并测一封  
   - 无 SMTP：确认后台「询价管理」可见，书面告知客户每日登录查看

5. **回传客户**  
   - 后台地址（IP/临时亦可）、初始账号（要求改密）  
   - 预览方法  
   - 提醒：备案前勿对公众宣传正式域名

### 4.2 域名可解析时

1. 解析：`www` → IP，`admin` → IP；按需 `@` → `www`  
2. 为 `www`、`admin` 配 HTTPS  
3. 用正式 `https://` 自测；证书报警则查解析/证书名是否匹配

### 4.3 收到备案号后

1. 写入页脚/官网信息  
2. 确认可链到工信部查询（若站点支持）  
3. **仍不开放**，直到客户验收并确认开放日

### 4.4 接近正式开放日

1. 与客户过验收清单（见第五节）  
2. 抽检手机端、询价、主栏目、图片  
3. 指导客户（或授权下代操作）：  
   `管理后台 → 官网信息 → 对外开放 → 开放 → 保存`  
4. 无痕窗口确认不再是「即将上线」  
5. 收尾：改密确认、对接人、培训、质保说明  

### 4.5 信息缺失时

| 缺什么 | 影响 | 你可先做什么 |
|--------|------|----------------|
| 无 IP/登录 | 无法部署 | 只指导买机、开安全组 |
| 无域名 | 无正式主机名证书 | 用 IP 内测 |
| 无备案号 | 不能合规对公众开 | 部署+预览，不打开开关 |
| 无联系文案 | 页脚空白 | 占位「待提供」，上线前必须换成正式文案 |
| 无询价邮箱 | 线索易漏 | 先靠后台列表，书面提醒客户每日查看 |
| 无开放日 | 排期不清 | 默认「备案通过后 +3～5 个工作日验收再开」 |

## 五、验收清单（与客户共同勾选）

- [ ] `https://www.…` 可开，证书正常  
- [ ] `https://admin.…` 可登录  
- [ ] 关闭=即将上线；预览=完整站  
- [ ] 各主栏目与图片正常  
- [ ] 询价可提交（邮箱或后台）  
- [ ] 手机端无明显错位/文字不可见  
- [ ] 客户已改后台密码  
- [ ] 「对外开放」状态符合客户意愿  

客户版截图与开关路径说明见《客户上线操作指引-阿里云》第四～五节。

## 七、费用与责任（内部对照）

| 项目 | 通常承担方 |
|------|------------|
| 域名、服务器、备案、云续费 | 客户 |
| 开发/部署/约定协助 | 合同约定（你实施） |
| 备案材料真实性 | 客户 |
| 主账号与续费保管 | 客户（你可协助加固） |
| 上线后改内容、跟询价 | 客户（你可培训/代运维按合同） |
| 质保期内程序缺陷 | 你方（以合同为准） |

## 八、对客户沟通口径（简要）

- 不收主账号密码；要协作子账号 + SSH。  
- 备案前可以内部预览，不能宣传「已正式上线」。  
- 海外临时站 ≠ 阿里云正式站；国内客户正式访问走本手册流程。  
- 选项拿不准：让客户发控制台截图，你远程指点，核验码由客户点。
